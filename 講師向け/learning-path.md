# 講師向けキャッチアップパス

## 目的

この資料は、講師が Azure IoT Hub の講義とデモを担当するための準備順序をまとめたものです。
操作手順を覚えるだけでなく、各操作について「誰が、どこへ、何を送り、どの結果を確認するのか」を説明できる状態を目指します。

## キャッチアップ完了の目安

- Azure IoT ソリューション全体の中で、IoT Hub の役割を説明できる
- デバイスの登録、認証、接続、テレメトリ送信の流れを説明できる
- D2C、Direct Method、Device Twin、C2D メッセージの用途を区別できる
- メッセージルーティングと、受信ツールによる確認の違いを説明できる
- デモ構成と本番構成の違い、今回の講義で扱わない範囲を説明できる

## 準備の順番

| Step | 学ぶこと | 実際に確認すること | 完了条件 |
| --- | --- | --- | --- |
| 1 | 既存デモの構成 | デバイスの接続、テレメトリ送信、クラウド側での受信を一通り実行し、画面表示とコードを対応させる | どのプログラムが、どの認証情報を使い、どこへ何を送っているか説明できる |
| 2 | Direct Method による即時操作 | クラウド側から開始・停止を呼び出し、デバイス側のハンドラー、応答、送信状態の変化を追う | 要求と応答の流れ、およびデバイスが未接続の場合の扱いを説明できる |
| 3 | Device Twin による設定同期 | Desired Properties で送信間隔を変更し、デバイスへの反映と Reported Properties の更新を確認する | Direct Method による操作と、Twin による状態・設定同期の違いを説明できる |
| 4 | メッセージの配送 | ルーティング条件とエンドポイントを一つ設定し、対象メッセージが配送されることを確認する | 組み込みエンドポイントでの受信確認と、後続サービスへの配送・保存の違いを説明できる |
| 5 | 本番利用への移行 | 切断・再送、資格情報、監視、容量、費用、デバイス登録方法の論点を確認する | 「デモで動く」状態から「運用できる」状態にするための確認事項を挙げられる |
| 6 | 講義全体の組み立て | 各操作を Azure IoT の全体図に戻し、導入からまとめまで通して説明する | 今回扱う範囲と対象外の範囲を明示し、各章を一つのユースケースでつなげられる |

## 各 Step の進め方

### Step 1: 既存デモの構成を理解する

1. IoT Hub、デバイス ID、デバイスアプリ、受信ツールの役割を図にする
2. デバイスアプリを起動し、接続ログを確認する
3. テレメトリを送信し、クラウド側で同じメッセージを確認する
4. 接続文字列を使う主体と、データの向きを確認する

この段階では、コードを変更するよりも、ログとコードの対応を追うことを優先します。

### Step 2: Direct Method の流れを追う

1. クラウド側から送信開始の Method を呼び出す
2. デバイス側で呼び出される処理と、返却するステータス・ペイロードを確認する
3. 送信停止の Method を呼び出し、テレメトリが止まることを確認する
4. Direct Method が即時応答を前提とする操作に向く理由を整理する

### Step 3: Device Twin の設定同期を確認する

1. Desired Properties に送信間隔を設定する
2. デバイスが変更を受け取り、送信間隔へ反映する処理を確認する
3. 適用結果を Reported Properties へ書き戻す
4. Direct Method、Device Twin、C2D メッセージの使い分けを表で説明できるようにする
    - C2D メッセージはデバイスごとにキューがあるので、デバイス側が動いていなくても後でとりに行ける

### Step 4: メッセージルーティングを理解する

1. テレメトリのプロパティまたは本文を使った条件を一つ決める
2. ルートと配送先を設定する
3. 条件に一致するメッセージと一致しないメッセージを送り、結果を比較する
4. IoT Hub は長期保存先ではなく、後続サービスへデータを渡す入口であることを確認する

### Step 5: 本番化の論点を整理する

次の問いに対して、デモ構成の制約と本番で必要になる検討を説明できるようにします。

- デバイスが切断した場合、未送信データと再送をどう扱うか
- 資格情報をどう保護し、更新し、失効させるか
- データが届かない場合、どのログやメトリックを確認するか
- 台数、送信頻度、メッセージサイズから容量と費用をどう見積もるか
- 多数のデバイスを登録するとき、手動登録から何へ移行するか

### Step 6: 講義として通して確認する

1. 工場の温度センサーという共通ユースケースで全章をつなぐ
2. 全体像、接続、送信、制御、状態同期、配送、本番化の順に説明する
3. デモを含めてリハーサルし、操作待ち時間と失敗時の代替画面を確認する
4. まとめで、各機能をどの場面で選ぶか問いかける

## 最終チェック

- [ ] デモ用の IoT Hub とデバイス ID が準備されている
- [ ] デバイスアプリの起動方法と必要な設定値を把握している
- [ ] D2C テレメトリをクラウド側で確認できる
- [ ] Direct Method による開始・停止を実演できる
- [ ] Device Twin による送信間隔変更と適用結果を確認できる
- [ ] デモ失敗時に見せるログまたは画面を用意している
- [ ] 90 分版と 120 分版の省略箇所を把握している
- [ ] 終了後に削除するリソースを把握している
