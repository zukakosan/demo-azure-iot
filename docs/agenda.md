# Azure IoT Hub 入門: デバイス接続から双方向通信まで

## ワークショップ概要
- 目的: IoT Hub の役割を理解し、デバイスの接続、データ送信、制御、状態同期を使い始めるための基礎を学ぶ
- 対象レベル: L100-200
- 所要時間: 90-120 分（以下は休憩・質疑を含む 120 分版）
- 形式: 座学講義 + 講師によるデモ。参加者が操作するハンズオンは含めない
- 対象者: これから Azure IoT Hub を使い始める人
- 前提知識
    - Azure のリソース、サブスクリプション、リソースグループに関する基礎知識
    - IoT や MQTT の事前知識は必須ではない

## 講義のフォーカス
Azure IoT の全体像は、IoT Hub の位置づけを理解するための導入として扱う。本編は IoT Hub の基本機能と、デモを通した動作の理解に集中する。

導入では、デバイスから保存・分析・可視化・制御までの全体図を示す。代表的なサービスと直接接続・エッジ経由の違いを短く紹介し、「今回はどこを扱うか」を明確にする。サービスの網羅的な比較や選定は到達目標に含めない。

全体図と接続パターンの整理は、Microsoft Learn の [Azure IoT とは](https://learn.microsoft.com/ja-jp/azure/iot/iot-introduction) を参考にする。

## 到達目標
- Azure IoT ソリューション全体の中で、IoT Hub の役割と担当範囲を説明できる
- デバイス登録、認証、接続、テレメトリ送信・受信確認の流れを説明できる
- D2C、Direct Method、Device Twin、C2D メッセージの典型的な用途を区別できる
- 受信したデータを後続の保存・分析サービスへ配送する流れを説明できる
- デモ構成と本番利用の違い、および本番化前に確認すべき事項を挙げられる

## 共通ユースケース
工場に設置した温度センサーを題材に、同じデバイスとデータを通して各機能の関係を追う。今回はクラウドへ直接接続できるデバイスを想定し、デモではローカル PC 上のプログラムで模擬する。

1. デバイス ID を登録し、温度センサーを IoT Hub へ接続する
2. 温度テレメトリを送信し、受信ツールで内容を確認する
3. 条件に応じて後続サービスへ配送する構成を考える（図とメッセージ例で説明）
4. Direct Method でテレメトリ送信を開始・停止する
5. Device Twin で送信間隔を変更し、デバイスが適用した結果を確認する

## デモの範囲と成功イメージ
操作手順の暗記ではなく、「誰が送信し、どこを経由し、何を確認するか」を見せる。

| 見せる操作 | 確認する結果 |
| --- | --- |
| Hub 作成手順の説明とデバイス ID 登録 | Hub とデバイス ID の関係が分かる |
| シミュレートデバイスの接続 | デバイス側の接続ログが確認できる |
| Direct Method で送信開始・停止 | メソッドの応答と、送信ログの変化が確認できる |
| D2C テレメトリの受信 | デバイスが送った温度データを IoT Explorer などで確認できる |
| Desired Properties で送信間隔変更 | デバイスの送信間隔が変わり、Reported Properties で適用結果を確認できる |

後続サービスへの配送・保存・可視化は、構成図とデータ例で説明し、ライブデモの必須範囲には含めない。作成待ち時間を避けるため準備済みの Hub を用意し、失敗時に切り替える画面・ログも準備する。

デモの基本操作と、メトリック確認・後片付けの補足は、[IoT Hub クイックスタート](https://learn.microsoft.com/ja-jp/azure/iot-hub/quickstart-send-telemetry-cli) を参考にする。

## 本番化で扱う範囲
デモから本番へ進む際の問いを示す。個別システムの要件定義や詳細設計を、この講義だけで完了することは目指さない。

- 資格情報: デバイスとバックエンドの認証をどう分け、秘密情報をどう保護・更新・失効するか
- 切断・再送: 接続が切れたとき、未送信データや重複をどう扱うか
- 容量・費用: 台数、送信頻度、サイズから、どの程度の負荷と費用を想定するか
- 監視: データが届かない場合にどこを確認し、誰が対応するか
- 台数拡大: 手動登録から自動プロビジョニングへ進む際に、何を検討するか

デバイス側・サービス側・管理操作の区別は [IoT Hub SDK](https://learn.microsoft.com/ja-jp/azure/iot-hub/iot-hub-devguide-sdks)、手動登録から DPS への導線は [デバイスのプロビジョニング](https://learn.microsoft.com/ja-jp/azure/iot-hub/iot-hub-devguide-identity-registry#device-provisioning) を参考にする。

エッジ環境の構築、後続の分析基盤の実装、多数台への一括管理、OTA 更新、証明書運用や災害復旧の詳細は、付録または次の学習テーマとする。
