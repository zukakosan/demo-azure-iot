# 3. IoT Hub の基本

## この章の目的
IoT Hub が担う役割、デバイス接続、Device-to-Cloud テレメトリの基本を理解する。

## 聞き手に持ち帰ってほしいこと
- IoT Hub はデバイスごとの ID と資格情報を使って接続を管理する
- D2C はデバイスからクラウドへ送る通常のテレメトリやイベントである
- IoT Hub は一時的な切断や再接続を前提に使う

## 扱う内容
### IoT Hub の役割
- デバイスとクラウド間の安全な双方向通信
- デバイスごとの ID と認証情報の管理
- デバイスからのテレメトリ取り込み
- クラウドからの指示とデバイス状態の管理
- 条件に応じた後続サービスへのメッセージ配送

IoT Hub はデバイス接続とメッセージングの基盤であり、データの長期保存・分析は後続サービスが担当する。

### デバイスの接続
- 主な対応プロトコル: MQTT、AMQP、HTTPS
- 各デバイスに一意の Device ID と資格情報を割り当てる
- 一時的な切断や再接続が発生することを前提にする

### Device-to-Cloud（D2C）
- デバイスからクラウドへテレメトリやイベントを送信する
- 例: 温度、湿度、稼働状況、アラート
- 共通ユースケースでは、温度センサーが定期的に測定値を送信する

## 話す流れ
1. IoT Hub を「デバイス接続の入口」として説明する
2. Device ID と資格情報により、デバイス単位で管理できることを説明する
3. 温度テレメトリを例に D2C の流れを説明する
4. Basic と Standard の違い、SKU 選択は後半の本番化観点にも関係することを示す

- Device ID、資格情報、IoT Hub、D2C メッセージの関係図
- シミュレートデバイスが IoT Hub に接続してテレメトリを送る図

## 強調するポイント
- デバイス資格情報は共有しない
- IoT Hub への送信成功と、後続の業務処理完了は別である
- D2C は「データを送る」、Device Twin や Direct Method は「制御や状態同期」に使う

## よくある誤解
- IoT Hub の接続文字列をアプリ全体で 1 つ共有すればよい
- IoT Hub に送信できたらデータ保存まで完了している
- MQTT を知っていないと IoT Hub は理解できない

## 理解度確認
- Device ID は何のために必要か
- D2C メッセージの典型例は何か
- IoT Hub が長期保存サービスではないとはどういう意味か
