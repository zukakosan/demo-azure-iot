# 1. Azure IoT の全体像

## この章の目的
Azure IoT Hub 単体の説明に入る前に、デバイス、エッジ、クラウド、保存・分析・可視化サービスがどのように分担するかを俯瞰する。

## 聞き手に持ち帰ってほしいこと
- IoT ソリューションは、デバイス接続だけでなく、取り込み、配送、保存、分析、可視化、制御までを含む
- IoT Hub はデバイス接続と双方向通信の中心であり、データ基盤そのものではない
- Azure IoT Operations、Azure Device Registry、Microsoft Fabric などは役割が異なる

## 扱う内容
### デバイスから価値を得るまでの流れ
1. デバイスや設備がデータを生成する
2. クラウドまたはエッジでデータを取り込む
3. 必要に応じてデータを変換・配送する
4. データを蓄積・分析・可視化する
5. 分析結果を通知やデバイス制御へつなげる

### 主な Azure サービス
- Azure IoT Hub
    - デバイスをクラウドへ接続し、双方向通信とデバイス管理を行う
- Azure IoT Operations
    - エッジで産業機器を接続し、データの収集・変換・クラウド連携を行う
- Azure Device Registry
    - デバイスや設備を Azure リソースとして一元管理する
    - Azure IoT Operations との連携は一般提供、IoT Hub との統合はプレビュー
- Microsoft Fabric
    - IoT データの蓄積・リアルタイム分析・可視化・AI 活用を行う代表的なデータ基盤

## 話す流れ
1. 温度センサーの例を使い、データが生まれてから意思決定や制御に使われるまでを説明する
2. IoT Hub の位置づけを「入口」として説明する
3. 保存、分析、可視化は別サービスと組み合わせることを強調する
4. クラウド接続とエッジ接続の話へつなげる

## 図・デモで見せるもの
- 温度センサー → IoT Hub → ルーティング → 保存・分析 → 可視化・通知、という全体アーキテクチャ図
- IoT Hub が担当する範囲と、後続サービスが担当する範囲を色分けした図

## 強調するポイント
- IoT Hub は「デバイスを安全につなぐための入口」である
- 長期保存、分析、可視化まで IoT Hub だけで完結させようとしない
- IoT はデバイス、ネットワーク、クラウド、運用の責任範囲を分けて考える

## よくある誤解
- IoT Hub に送れば自動的に分析や可視化までできる
- Azure IoT Operations は IoT Hub の単純な後継サービスである
- デバイス管理とデータ分析は同じサービスで行うものだ
