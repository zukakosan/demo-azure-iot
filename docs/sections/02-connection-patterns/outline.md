# 2. 接続パターンとサービスの選択

## この章の目的
クラウド直接接続とエッジ経由接続を要件から考え、エッジ経由には Azure IoT Operations と Azure IoT Edge の選択肢があると理解する。今回は IoT Hub への直接接続を本編で扱う。

## 聞き手に持ち帰ってほしいこと
- デバイスがクラウドへ直接接続できる場合は IoT Hub が中心になる
- 産業プロトコル、低遅延、オフライン、現場閉域網が重要な場合はエッジ接続を検討する
- 実際の現場ではクラウド接続とエッジ接続が混在する

## 扱う内容
### クラウド接続パターン
- デバイスが MQTT、AMQP、HTTPS などでクラウドへ接続する
- 地理的に分散したデバイスや、クラウドで一元管理するシナリオに適する
- 中心となるサービス: Azure IoT Hub

### エッジ接続パターン
- デバイスや産業機器が現場のエッジ環境へ接続する
- OPC UA などの産業プロトコル、現場での低遅延処理、直接インターネットへ接続できない環境に適する
- 本章で中心に紹介するサービス: Azure IoT Operations

Azure IoT Edge も、現在サポートされているエッジ接続の選択肢の一つである（2026-09-08 確認）。デバイス上でコンテナー化した処理を実行し、IoT Hub へのゲートウェイとしても利用できる。本章ではその位置づけの紹介に留め、IoT Operations との詳細比較や構築手順は扱わない（[IoT Edge の概要](https://learn.microsoft.com/ja-jp/azure/iot-edge/about-iot-edge)、[ゲートウェイとしての利用](https://learn.microsoft.com/ja-jp/azure/iot-edge/iot-edge-as-gateway)、[リリースとサポート期間](https://learn.microsoft.com/ja-jp/azure/iot-edge/version-history)）。

### ハイブリッドパターン
- クラウド接続とエッジ接続を組み合わせる
- 拠点、設備、ネットワーク要件ごとに接続方法を使い分ける

### シンプルな選択基準
| 要件 | 主な選択肢 |
| --- | --- |
| デバイスをクラウドへ直接接続できる | Azure IoT Hub |
| OPC UA などのプロトコル変換が必要 | Azure IoT Operations |
| 現場で低遅延処理やオフライン動作が必要 | Azure IoT Operations |
| デバイス上でコンテナー処理を行い、IoT Hub へ接続する | Azure IoT Edge + IoT Hub |
| クラウド接続とエッジ接続が混在する | ハイブリッド |
| デバイスや設備を Azure リソースとして管理したい | Azure Device Registry |
| データを蓄積・分析・可視化したい | Microsoft Fabric などの後続サービス |

## 話す流れ
1. 同じ温度センサーでも、ネットワークや現場要件によって接続パターンが変わることを説明する
2. クラウド接続、エッジ接続、ハイブリッドを比較する
3. サービス名ではなく、要件から選ぶ姿勢を強調する

| Slide | タイトル | 目的 | レイアウト / ビジュアル | 主なメッセージ |

## 図・デモで見せるもの
- クラウド直接接続、エッジ経由接続、ハイブリッド接続の 3 パターン図
- 「要件 → 接続パターン → 主要サービス」の対応表

## 強調するポイント
- IoT Hub はクラウド接続パターンの中心
- Azure IoT Operations は産業機器やエッジ要件がある場合に検討する
- Azure IoT Edge も冒頭図・紹介見出し・整理表に明記し、注記だけにしない。構築手順や詳細比較は扱わない
- 最初から 1 つのサービスだけで全体を決めない

## よくある誤解
- すべての IoT シナリオで IoT Hub だけを使えばよい
- エッジ接続はクラウド接続より常に高度で優れている
- Azure IoT Operations を使うと IoT Hub が不要になる

## 理解度確認
- 工場内の OPC UA 対応設備を接続したい場合、どのサービスを検討するか
- デバイスがインターネットへ直接接続できる場合、中心になるサービスは何か
- ハイブリッド構成が必要になる典型的な理由は何か
