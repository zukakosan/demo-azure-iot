## 章の目的・範囲
聞き手がクラウド直接接続とエッジ経由接続の違いを説明し、今回の本編・デモは IoT Hub への直接接続を扱うと理解できることを目的とする。対象は IoT Hub をこれから使う L100-200 の受講者。サービスの網羅的な選定、構築手順、認証・実装の詳細は対象外。

| ページ | 説明対象・必要な理由 | 既出の前提 | 新たに分かること | 図表の根拠 |
| --- | --- | --- | --- | --- |
| 02-01 | 接続パターンを決める3つの要件。製品名から選ばないための判断軸 | 前章のデバイスからクラウドへの全体像 | 通信方式、ネットワーク、処理場所を確認する | 投影本文に紐付けた公式資料と3軸の問い |
| 02-02 | IoT Hub へのクラウド直接接続。本編の構成を位置づける | 3つの要件 | デバイス、Hub、後続サービスの配置と役割 | 原稿の直接接続図、温度データの向き、該当出典 |
| 02-03 | IoT Operations によるエッジ経由接続。現場処理との違いを示す | 直接接続の構成 | 現場の実行基盤、データ経路、オフライン条件、IoT Edge の短い位置づけ | 原稿の工場・実行基盤の境界、接続・処理・配送の図、該当出典 |
| 02-04 | ハイブリッド構成と今回の対象範囲。全拠点を一方式に限定しない | 直接接続とエッジ経由 | 要件別の併用と、本編で扱う経路 | 原稿の2経路と比較表。顧客の採用構成ではなく説明用の例 |

構成は4枚を維持したが、枚数・時間を固定制約にしていない。アジェンダの時間配分は変更していない。第3章の認証・SDK、第4章の制御・状態同期、第5章の配送設定は先取りしない。

## 修正元と生成方法
- 投影タイトル・本文・表・図の修正元: [slides.md](../../slides.md)
- 概要とスライド一覧: [outline.md](../../outline.md)
- 使用した生成処理: [build-slides.ps1](../../build-slides.ps1)
- 一致検査: [verify-regeneration.ps1](../../verify-regeneration.ps1)

今回の生成では旧 JavaScript 版を使用していない。PowerPoint COM でテンプレートの本文スライド（2枚目）を読み取り専用で開き、別名保存して複製する方式を使用。原稿の投影本文・表・Mermaid のノード、矢印、グループを読み、編集可能なテキスト・表・図形として配置した。

本文と図を生成コード内に重複保持せず、各段落・セル・ノード・矢印のラベルを原稿と照合している。ノートには原稿のページ内容、講師補足、時間、完全な出典 URL、原稿ハッシュを保存した。

今回必要だった変更は、IoT Edge の追加段落を3枚目へ配置する処理、段落数変更を検出する生成前チェック、別の検査出力先を指定する引数。投影原稿の時間・枚数表記と outline のタイトル一覧も現在の方針に揃えた。

## ファイル検査と安定性
同じ入力と生成処理で2回続けて生成し、両方を実際の PowerPoint で保存・再オープンした。

| 検査 | 結果 |
| --- | --- |
| 原稿の4セクション・段落数・図構造 | 両方とも合格 |
| 本文全段落・表セル・図ラベルの一致 | 両方とも合格。IoT Edge 段落も含む |
| 図の接続先・矢印方向・グループ内配置 | 両方とも合格 |
| テキスト・表セルの収まり（許容差2 pt） | はみ出し候補0件 |
| 元テンプレートの SHA256 | 生成前後で変更なし |
| PPTX の保存と再オープン、PDF 出力 | 両方とも成功 |
| 原稿・テンプレートの入力ハッシュ | 2回とも一致 |
| 本文・図形配置・レイアウト・リンク・ノート | 全4枚一致（下記識別子を除外） |
| 1600 x 900 PNG の展開後画素 | 全4枚一致 |
| スライド内の編集可能な図形数 | 15 / 20 / 25 / 18。本文を一枚画像にしていない |
| スライド内の画像数 | 全4枚0。マスター・レイアウトは継承 |
| 出典ハイパーリンク数 | 1 / 3 / 6 / 2。全ページのノートに完全な URL あり |
| テンプレートの既知のダミー文字 | 検査パターンに該当なし |

PPTX 構造比較では、PowerPoint が保存時に生成する `creationId`、`modId`、表の `colId`、`rowId` を除外した。最初の比較では表の列IDが異なったが、描画画素は一致していた。本文・位置・書式を比較から除外したわけではない。

安定性の対象は同じ Windows / PowerPoint 環境での2回の実行。PPTX バイナリ全体の一致、独立したAIによる再構成の一致、異なるPC・フォント・Office版での表示一致は検証していない。リンクの存在と内容は検査したが、全リンクのクリック操作やネットワーク到達性は未検証。

エディター診断では、既存の生成処理に未使用変数 `teal` の警告が1件ある。今回追加した検査処理と変更したMarkdownに診断エラーはなく、生成・一致検査とも正常終了した。

## 再生成手順
前提: Windows、PowerShell 7、デスクトップ版 PowerPoint。リポジトリルートから実行する。次の例は一意の作業フォルダーに出力し、既存の成果物や手作業で編集したファイルを上書きしない。

```powershell
$section = Join-Path $PWD 'docs/sections/02-connection-patterns'
$run = Join-Path $section ('verification/check-' + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $run | Out-Null
& "$section/build-slides.ps1" -ValidateOnly
& "$section/build-slides.ps1" -Output "$run/first.pptx" -VerificationDirectory "$run/first"
& "$section/build-slides.ps1" -Output "$run/second.pptx" -VerificationDirectory "$run/second"
& "$section/verify-regeneration.ps1" -First "$run/first.pptx" -Second "$run/second.pptx" -FirstRender "$run/first" -SecondRender "$run/second" -Report "$run/stability.json"
```

各 PPTX と同じ場所に PDF、検査フォルダーに PNG と JSON を生成する。原稿の段落数や図構造を変更した場合は、生成前チェックの結果に従って配置も調整し、機械検査だけでなく画像レビューを再実施する。
