# 6. デモ: IoT Hub の初期デプロイとデバイス接続

## この章の目的
ハンズオンではなく、IoT Hub を使い始めるときの初期デプロイとデバイス接続のイメージを短時間で伝える。

## 聞き手に持ち帰ってほしいこと
- IoT Hub を作成し、デバイス ID を登録してからデバイスを接続する
- デバイスは個別の資格情報を使って IoT Hub に接続する
- D2C テレメトリ送信と Device Twin による状態同期の基本的な流れを理解する

## デモの狙い
- IoT Hub を使い始めるときの初期デプロイの流れを理解する
- IoT Hub、デバイス ID、接続文字列、シミュレートデバイスの関係を理解する
- D2C テレメトリと Device Twin による状態同期のイメージをつかむ

## デモシナリオ
1. IoT Hub を作成する
2. デバイス ID を登録する
3. デバイス接続文字列を確認する
4. シミュレートデバイスから温度テレメトリを送信する
5. IoT Hub 側でメッセージ受信を確認する
6. Device Twin の Desired Properties で送信間隔を変更する
7. デバイスが設定を適用し、Reported Properties を更新する
8. Desired と Reported が一致したことを確認する

## デモで伝える対応関係
| 見せる操作 | 伝えるポイント |
| --- | --- |
| IoT Hub 作成 | IoT Hub はデバイス接続の入口である |
| デバイス ID 登録 | IoT Hub はデバイス単位で認証・管理する |
| 接続文字列確認 | デバイスは個別の資格情報で接続する |
| テレメトリ送信 | D2C はデバイスからクラウドへの通常のデータ送信である |
| 受信確認 | IoT Hub は取り込み口であり、長期保存や分析は後続サービスが担当する |
| Desired Properties 更新 | クラウド側がデバイスに期待する構成を表す |
| Reported Properties 確認 | デバイス側で実際に適用された状態を確認する |

## 話す流れ
1. デモは操作手順の暗記ではなく、構成要素の関係を見るものだと伝える
2. IoT Hub とデバイス ID を作成する
3. 接続文字列を使ってシミュレートデバイスを接続する
4. 温度テレメトリを送信し、IoT Hub 側で受信を確認する
5. Device Twin の Desired Properties を更新し、Reported Properties で適用状態を確認する

## 図・デモで見せるもの
- Azure portal または Azure CLI による IoT Hub 作成
- デバイス ID 登録画面
- シミュレートデバイスの送信ログ
- IoT Hub 側の受信確認
- Device Twin の Desired / Reported Properties

## 強調するポイント
- 接続文字列やキーはデモ用として扱い、本番では保護とローテーションが必要
- IoT Hub への送信確認と、保存・分析への反映は別の確認ポイントである
- Device Twin は「クラウドが期待する状態」と「デバイスが報告する状態」を分けて見る

## よくある誤解
- IoT Hub を作成すればデバイスが自動的に接続される
- デバイス接続文字列を複数デバイスで共有してよい
- Desired Properties を変更すれば即時に適用完了となる

## 理解度確認
- デバイスを IoT Hub に接続する前に何を登録する必要があるか
- デバイス接続文字列は何に使うか
- Desired Properties と Reported Properties は何が違うか
